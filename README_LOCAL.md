# Great Equalizer — локальный сайт Ozon / WB

Приложение работает на вашем компьютере и открывается в обычном браузере.
Адрес после запуска: **http://127.0.0.1:8765**. Хостинг, Nginx и Jupyter для теста не нужны.

## Запуск в Windows

1. Установите Python 3.10 или новее с python.org. При установке включите Python в PATH.
2. Полностью распакуйте архив в отдельную папку.
3. Дважды нажмите **run_local.bat**. При первом запуске он создаст окружение
   `.venv-web` и скачает библиотеки; нужен интернет.
4. Откроется браузер с демонстрацией. Если вкладка не открылась, введите
   **http://127.0.0.1:8765** вручную.

Окно Python оставляйте открытым. Закрытие окна или Ctrl+C останавливает сайт.
Сервис слушает только ваш компьютер. Для подключения с других устройств он не настраивался.
Если порт занят, можно запустить `python web_app.py --port 8767 --open-browser`
из окружения с установленными зависимостями.

Linux/macOS или запуск вручную:

```bash
python -m venv .venv-web
# Активируйте окружение и затем выполните:
python -m pip install -r requirements-web.txt
python web_app.py --open-browser
```

## Сначала проверить демо

Демонстрация работает без ключей и не обращается к Ozon. В ней есть три товара
и две кампании-примера. Можно создать ещё одну, выбрать свободный товар, поменять
ограничение/ссылку и проверить изменение коэффициента. Изменения демо только в памяти;
кнопка «Демо» восстанавливает исходное состояние этой сессии браузера.

Коэффициент задаётся **на кампанию (стратегию Ozon) для конкурента WB**. Все товары
одной кампании используют его, но другие кампании имеют собственные значения.
Для отдельного SKU задаются галочка участия, ограничение цены и ожидаемая WB-ссылка.
Один товар не может быть в двух стратегиях; автоматического переноса из чужой кампании нет.

## Подключить свой кабинет

Нажмите **«Подключить Ozon»**, введите Client-Id и API-ключ. Сначала приложение
проверит чтение списка стратегий, затем загрузит ваш каталог. Сами ключи остаются
в памяти локального Python-процесса. В файл, localStorage и HTML они не записываются.
После перезапуска сервера их нужно ввести снова.

Настройки кампаний, ожидаемые WB-ссылки и состояния незавершённых изменений сохраняются
в `.local/web-state` в папке приложения, отдельно для кабинетов. Эту папку сохраняйте
между запусками. Не удаляйте её ради повторения неизвестного результата записи:
сначала перечитайте фактическое состояние Ozon.

## Если старая стратегия удалена

1. Нажмите **«Новая кампания»**.
2. Введите имя и стартовый коэффициент, например **0,960**.
3. Отметьте нужные товары. Укажите каждому ограничение цены и ожидаемую WB-ссылку
   через кнопку в колонке «WB-ссылка».
4. Нажмите **«Создать и включить»**.

Сайт создаст стратегию через API и сохранит её новый ID. Затем установит ограничения,
добавит выбранные товары, включит стратегию и проверит ссылки. Старый удалённый ID
не задан в рабочей конфигурации. Уже существующая кампания с тем же именем проверяется
и переиспользуется; текущий коэффициент у неё сохраняется. При одинаковых именах
нескольких стратегий нужно выбрать точный ID через список.

Выполнение записи не является общей транзакцией Ozon. При ошибке часть настроек могла
сохраниться. Созданный ID остаётся доступен, запись не повторяется автоматически.

## Работа с выбранной кампанией

- Переключатель **«Кампания»** выбирает стратегию. При переключении не меняются
  коэффициенты и состав других кампаний.
- Галочки и поля редактируют желаемые настройки. **«Применить выбор»** сохраняет
  ограничения и состав. Снятая галочка исключает товар только после применения.
- **«Обновить данные»** читает цены, коэффициент, индекс и ссылки.
- **«Проверить WB-ссылки»** может исключить конкретный товар с неверной или не
  подтверждённой за время ожидания ссылкой. Другие товары продолжают работать.
- **«Рассчитать коррекцию»** показывает предложение без записи.
- Поле коэффициента и **«Применить»** меняют коэффициент всей выбранной кампании:
  строго **0,94–1,00**, за операцию максимум **0,002**.

Средний индекс считается по фактическим участникам выбранной кампании, без нулей,
с одинаковым весом товаров. Другие кампании и не выбранные товары не входят в него.
Цель **0,98–1,01 включительно**. Пропуски не заменяются нулями. Нижние ограничения
цены ради среднего не уменьшаются.

Блок **«Тест одного цикла регулирования»** позволяет вручную проверить один цикл.
Сначала нужно сверить индекс API с AJ свежего шаблона и отметить это в форме.
Намерение изменения сохраняется до записи. По тем же старым данным повторной
коррекции нет. Для каждой кампании ожидание результата хранится отдельно.
**Расписание дважды в день в локальной тестовой версии не включено.**

Собственная WB-ссылка читается из стратегии, при пустой ссылке — из
`/v1/product/prices/details` (нужен Premium Pro). Ожидаемая ссылка служит для сверки:
публичного метода записи нового сопоставления или жалобы не найдено. Если ожидаемая
ссылка ещё не введена, это отдельный статус, а не доказательство несовпадения.

Индекс берётся из `self_marketplaces_index_data.price_index_value`. Он требует
сверки с AJ, а не подмены `self_wb_index`. Данные цены/индекса могут обновляться
с задержкой. Ограничение относится к предельной цене, скидка Ozon может сделать
покупательскую цену ниже. Продление 30-дневного таймера ограничений пока не реализовано.

## Файлы

`web_app.py` — локальный веб-сервер и фоновые операции; `ozon_strategy.py` — Seller API;
`web_demo.py` — демонстрация без сети; `web_static` — страница, стили и JavaScript;
`requirements-web.txt` — зависимости; `run_local.bat` — запуск Windows.

Backend и браузерные сценарии проверяются на демонстрационном API, реальные ключи
пользователя здесь не применялись. Windows-launcher подготовлен для запуска на ПК;
его выполнение в Windows проверяется пользователем. Тесты Python можно запустить
после установки `httpx` командой `python -m unittest discover -s tests -v`.
