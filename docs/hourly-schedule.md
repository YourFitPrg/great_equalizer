# Автокоррекция по интервалу: первый этап

Версия 0.4.0 добавляет настройку в карточку «Подтверждено товаров в кампании»:
переключатель, интервал **1–168 целых часов**, подтверждение сверки индекса,
ближайший запуск, результат последнего запуска и срок действия текущего сеанса.

1. Подключите кабинет и выберите кампанию.
2. Сохраните состав, WB-ссылки и ограничения через «Применить выбор».
3. Укажите интервал, подтвердите сверку индекса API с AJ, включите переключатель
   и нажмите «Сохранить расписание».
4. Первый запуск — через выбранный интервал. Само включение не меняет цену.
   Выключение переключателя сохраняется сразу; уже отправленный запрос может завершиться.

Расписание отдельное для каждой кампании и кабинета. Все включённые кампании
подключённого кабинета проверяются независимо от того, какая сейчас выбрана
в таблице. Планировщик использует сохранённые настройки, а не несохранённые поля страницы.

## Что делает один запуск

Используется тот же `StrategyService.cycle`, что у ручного теста:
свежие участники, WB-ссылки, ограничения и индекс; среднее только по фактическим
участникам, исключая нули. В [0,98;1,01] коэффициент сохраняется, вне диапазона
предлагается одна ступень 0,01 в границах 0,94–1,00. Нижние цены не снижаются.
Неполные/противоречивые данные блокируют коррекцию. Повтор по старым данным не выполняется.

Задание отмечается в JSON **до запуска**, намерение изменения коэффициента —
до HTTP-запроса. Ошибка записи не запускает слепой повтор. В двух сеансах одного
кабинета используются общее состояние и блокировка; параллельные циклы не складываются.
При занятой кампании/кабинете запуск ждёт освобождения до 5 минут. Более поздние
пропуски не догоняются серией изменений по устаревшим данным.

## Ключи и срок работы

На первом этапе ключ по-прежнему только в RAM активного сеанса:
**30 минут без действий и максимум 8 часов после входа** в серверном режиме.
Обновление статуса расписания не продлевает сеанс. Действия пользователя на странице
поддерживают активность через отдельный защищённый запрос, не снимая абсолютный предел.

Поэтому интервал не гарантирует выполнение, если к нужному времени сеанс завершился.
Простого открытого фонового таба недостаточно. После выхода, истечения сеанса,
смены подключённого кабинета или перезапуска нужен повторный ввод ключа.
Если у кабинета остался другой действующий сеанс, он может продолжать выполнять
общее расписание; один цикл не будет дублироваться между сеансами.

Настройки сохраняются в `/var/lib/great-equalizer/<хеш Client-Id>.json`, поле
`schedules`, без ключей. После повторного подключения будущий запуск сохраняется;
если он уже пропущен, следующий назначается через интервал от подключения.
Прерванный при перезапуске запуск не повторяется автоматически. Пауза не удаляет
товары и не выключает саму стратегию в Ozon.

Автономная работа после выхода относится ко второму этапу:
[варианты хранения и отдельного исполнения](external-key-storage.md).

## API и исполнение

* `POST /api/schedule`: `strategy_id`, `enabled`, `interval_hours`, `metric_confirmed`.
* `GET /api/schedule/status?report_at=...`: статус; отчёт только если изменился.
* `POST /api/activity`: действительная активность пользователя, CSRF + Origin.
* Планировщик внутри единственного процесса проверяет сроки каждые 5 секунд.
* Запускайте **один worker**. Для нескольких процессов/серверов понадобится
  внешняя очередь и межпроцессная блокировка; текущая служба остаётся однопроцессной.

Неизвестный Client-Id отображается как «Кабинет Ozon». Для пяти заданных ID
используются имена «Носки», «Игрушки_Хрюшки», «Обувь», «Сладкий Дом», «Твой Фитнес».
