# Цены WB/Ozon и зависимость от Premium Pro

Проверено по официальному Swagger Seller API **13 ноября 2026 года**.
В описании `/v1/product/prices/details` прямо указано: «Доступно для продавцов
с подпиской Premium Pro». Обычная подписка Premium не равнозначна Premium Pro.
HTTP 403 также может означать нехватку прав ключа, поэтому приложение не определяет
отсутствие подписки только по этому коду.

| Данные приложения | Источник | Что будет без доступа к детальному методу |
|---|---|---|
| Цена на WB | `prices[].price_indexes[].self_index_data.min_price`, только собственная ссылка WB | Нет доступа / пустая ячейка |
| Запасная собственная цена WB | `prices[].weight_index[].self_wb_min_competitor_price` и `self_wb_url` | Нет доступа / пустая ячейка |
| Цена на OZON | `prices[].customer_price` | Нет доступа / пустая ячейка |
| Запасная WB-ссылка для сверки | Собственные поля `self_index_data.url` и `self_wb_url` того же метода | Проверяем ссылку через обычный метод стратегии |
| SKU, артикул, каталог | `/v3/product/list`, `/v3/product/info/list` | Используются обычные методы |
| Предельная цена, нижнее ограничение, индекс | `/v5/product/info/prices` | Используется обычный метод |
| Кампания, состав, коэффициент, включение, ссылка стратегии | `/v1/pricing-strategy/*` | Используются обычные методы |

Для последних трёх групп в спецификации нет требования Premium Pro. Реальная
доступность зависит также от прав API-ключа и наполнения ответа для товара.
Отсутствующий индекс не заменяется нулём: неполные данные блокируют коррекцию.

## Какие именно цены показываются

«Цена на WB» — собственная цена из данных Ozon, а не запрос в витрину WB.
Приоритет имеет раздел собственных внешних цен, запасной источник — собственный
блок WB `weight_index`. Эти значения могут различаться: они не смешиваются,
источник виден в подсказке ячейки. Чужие `external_index_data` и собственные ссылки
на другие площадки исключены. При нескольких карточках WB или разных валютах
цена отмечается как неоднозначная. Если валюта отличается от RUB, показывается её код.

Swagger описывает `customer_price` как «Цена, которую видит покупатель».
Отдельного признака оплаты картой Ozon или кошельком WB у этих полей нет.
Поэтому приложение не гарантирует совпадение с ценой конкретного способа оплаты,
не вычитает расчётные 3% и не выдаёт предельную цену за покупательскую.
Для подтверждения соответствия полям ЛК нужна сверка свежих значений по одному SKU.
Данные Ozon могут обновляться с задержкой.

Эти колонки справочные. Среднее и коррекция по-прежнему используют только
`self_marketplaces_index_data.price_index_value` из `/v5/product/info/prices`,
по фактическим участникам выбранной кампании, исключая нули. Цена WB и
`self_wb_index` из Premium Pro не подставляются вместо этого индекса.

## Поведение при отказах

* Ошибка дополнительного метода не прерывает чтение каталога и основных цен.
* При наличии подтверждённой WB-ссылки в `/v1/pricing-strategy/product/info`
  управление составом и коэффициентом работает без детальных цен.
* Если оба источника ссылки недоступны, текущие участники сохраняются;
  проверка ссылки и изменение коэффициента блокируются до подтверждения.
* После нового добавления или включения приложение ждёт появления ссылки
  в обычном методе стратегии. Если подтвердить её не удалось, откатывается
  участие только новых/вновь активированных неподтверждённых товаров.
* Подтверждённое несовпадение карточки или несохранённый нижний порог по-прежнему
  приводит к исключению конкретного товара.
* Запрет доступа кешируется на пять минут, временная ошибка на 30 секунд,
  отдельно для каждого подключения. Цены не кешируются. После смены подписки
  или прав ключа можно сразу переподключить кабинет.

Новые поля в JSON строки: `wb_price`, `ozon_customer_price` — деньги
`{amount, currency, source, url?}` или `null`; `prices_details_status`,
`prices_details_note`, `wb_price_note`. Состояние доступа — `prices_details_access`.
`link_status=unavailable` означает невозможность проверки, а не несовпадение.
