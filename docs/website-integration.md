# Веб-версия: кампании Ozon по WB

Проверка чужой стратегии: для фактической привязки используется
официально рекомендованный `/v1/pricing-strategy/strategy-ids-by-product-ids` пакетами
до 50 ID. `product/info` используется для цены/ссылки, а не как единственное доказательство
участия. Пустой/нулевой UUID не считается другой кампанией. Иная пользовательская
привязка подтверждается составом той стратегии; удалённые и неподтверждённые ID не
объявляются действующим участием. Подтверждённая системная `MIN_EXT_PRICE` снимается
только с выбранных товаров после записи ограничения. Её общий статус не меняется.
В выводе отдельно показаны фактический ID и ID из данных цены.


Версия 0.2.2 не отправляет `price_strategy_enabled=ENABLED`: этот общий переключатель
мог переводить товар в системную стратегию после добавления в пользовательскую.
При сохранении ограничения передаётся только `UNKNOWN`, принадлежность задаёт
`products/add(strategy_id=…)`, активность кампании — `status(strategy_id=…)`.
После последней записи повторно подтверждается фактическая целевая привязка.

Подтверждённый состав — пересечение списка выбранной стратегии и результатов
`strategy-ids-by-product-ids`, с проверкой явно неактивного участия и противоречащих
данных цены. Среднее и счётчик используют подтверждённый состав. Исходный список
остаётся в `listed_member_count`/`membership_evidence`; он не считается успехом сам
по себе. Повторное добавление опирается на привязку и активность, поэтому устаревший
список не мешает восстановить товары, удалённые пользователем из системной стратегии.
`GET /api/diagnostics` отдаёт JSON последней проверки и журнал записей без credentials.

Актуальный результат — локальный сайт. [Запуск и действия пользователя](../README_LOCAL.md).
Каждая кампания соответствует пользовательской стратегии Ozon с конкурентом WB:
свой состав, свой коэффициент и своё среднее. В браузере можно создавать кампании
и переключаться между ними. Товар Ozon участвует только в одной стратегии.

## Компоненты

- `web_app.py` — FastAPI, сессия браузера, очередь операций и хранение настроек.
- `web_static/` — HTML/CSS/JavaScript без внешних CDN и сборки Node.js.
- `ozon_strategy.py` — самостоятельный API-клиент и сервис выбранной стратегии.
- `web_demo.py` — изолированные демонстрационные данные, без сети и ключей.
- `run_local.bat` и `requirements-web.txt` — запуск на Windows.

Для обычной работы достаточно распаковать `exports/ozon-local-web.zip` и запустить
`run_local.bat`. Uvicorn слушает `127.0.0.1:8765`. Nginx и Jupyter не требуются.
Сайт предназначен для локального теста; публичное размещение отдельно не настраивалось.

## Пользовательский интерфейс

Над таблицей: выбор кампании, создание новой, активность, общий коэффициент с
границами 0,94–1,00 и сеткой 0,01, средний индекс с целью 0,98–1,01,
число участников/ненулевых/нулей/пропусков. Коэффициент относится к выбранной кампании,
а не ко всему кабинету. В строках его значение показывается без отдельного редактора.

В таблице: галочка участия, артикул/название/SKU, индивидуальное ограничение,
подтверждение сохранения, предельная цена, цена по стратегии, индекс, статус WB
и фактическое участие. Через колонку WB открываются ожидаемая и фактическая ссылки,
источник, ID стратегии и дата цены. Время проверки показывается отдельно по Новосибирску.

Редактирование поля или галочки само по себе не изменяет Ozon. Действия выполняются
кнопками. Новая кампания создаётся и включается вместе с выбранными товарами.
При неверной WB-ссылке исключается отдельный товар; остальные продолжают работу.
Если ожидаемая ссылка ещё не задана, статус «expected_missing» блокирует коррекцию,
но не объявляет сопоставление неверным. До применения выбранных товаров ссылка обязательна.

## Контракт Python-модуля

`StrategyService(api, strategy_id)` работает с одной выбранной стратегией.
Для нескольких кампаний используются разные экземпляры и состояния по ID.

| Функция/метод | Действие |
| --- | --- |
| `list_strategies(api)` | Читает стратегии с пагинацией; ничего не включает |
| `ensure_strategy(api, strategy_name=…, initial_coefficient=…, state=…, persist=…)` | Создаёт одну кампанию либо восстанавливает известный ID/совпадающее имя; сохраняет намерение до записи и ID сразу после ответа |
| `service.snapshot(products)` | Читает строки и среднее фактических участников |
| `service.apply_selection(products)` | Сохраняет ограничения, подтверждает их, добавляет/исключает товары, включает и проверяет ссылки |
| `service.verify(products)` | Проверяет WB; может исключить конкретный товар |
| `service.plan(report)` | Вычисляет предложение без записи |
| `service.change_coefficient(value, expected_current=…, expected_members=…)` | Проверяет состав/старое значение, пишет малый шаг, перечитывает коэффициент |
| `service.cycle(products, state, write=…, metric_confirmed=…, persist=…)` | Один цикл регулирования со своим состоянием для каждой кампании |

Коэффициент существующей стратегии сохраняется при добавлении товаров и переключении.
Стартовый коэффициент новой задаётся в форме, исходно 0,960. API разрешает более широкий
диапазон 0,5–1,2; приложение ограничивает его правилом пользователя 0,94–1,00.

Перед созданием намерение сохраняется. После неопределённого результата запрос create
не повторяется вслепую: ID восстанавливается из записи или списка по точному имени.
При нескольких совпадениях нужен выбор ID. Подтверждённый HTTP 404 для сохранённого ID
позволяет при явном создании восстановить удалённую кампанию новой стратегией.

Новая пустая стратегия выключается до настройки. Сначала записывается ограничение
с `price_strategy_enabled=UNKNOWN`, подтверждается `min_price`, затем товары добавляются
в целевую стратегию, затем включается только сама стратегия по её ID.
Это не одна транзакция Ozon. При ошибке возможен частично применённый результат;
нужно перечитать фактическое состояние. Действия записи автоматически не повторяются.

## HTTP и очередь

| Маршрут | Действие |
| --- | --- |
| `GET /` | Страница |
| `GET /api/session` | Локальная сессия, CSRF-токен и режим |
| `GET /api/state` | Последнее состояние выбранной кампании и каталога |
| `GET /api/diagnostics` | JSON последней проверки, источники привязок и журнал записей без ключей/заголовков |
| `POST /api/jobs` | Операция в очереди: load/select/create/apply/verify/refresh/plan/coefficient/cycle/connect/demo |
| `GET /api/jobs/{id}` | Прогресс и результат только своей сессии |

Операции с Ozon выполняются в рабочих потоках. Браузер получает ID задания и опрашивает
прогресс. Одновременно в одной сессии выполняется одно задание; для записи одного
кабинета используются общие блокировки внутри процесса. Данные других кампаний
не меняются при выборе. Автоматического переноса товара из чужой стратегии нет.

Настройки хранятся в `.local/web-state` по хешу Client-Id. Ключи — только в памяти
процесса и не входят в возвращаемое состояние, cookie или файлы. Демосессии не сохраняют
данные в файлы. На локальном сервере включены ограничения Host, same-origin/CSRF,
HttpOnly-cookie и CSP без внешних скриптов. По перезапуску нужно снова ввести ключ.

Для переноса в существующий сайт бизнес-логику можно импортировать отдельно. Текущий
адаптер использует память одного процесса; масштабирование на несколько worker не поддерживается.
С версии 0.3.0 есть серверный режим с административным входом, HTTPS и подпутём.
См. [установку на yfweb](../DEPLOY_SERVER.md).

## Регулирование и пределы

Среднее — арифметическое, только по фактическим участникам выбранной кампании,
исключая ровно нули. Пропуски не заменяются нулями. Другие кампании и кандидаты не
входят в знаменатель. Внутри [0,98; 1,01] коэффициент не меняется. Вне вилки
предлагается одна соседняя ступень 0,01: при высоком среднем вниз, при низком вверх.
Ручной выбор допускает любое значение сетки 0,94–1,00, без ограничения одной ступенью.
Нижние цены не уменьшаются. При достижении границы без нужного среднего успех не объявляется.

До записи нужно сверить поле API `self_marketplaces_index_data.price_index_value`
с AJ свежего шаблона и проверить реакцию на малый шаг. Состояние ожидания хранится
отдельно по ID кампаний. Пока индекс/цена не обновились, новая автоматическая
коррекция не накапливается. После наблюдения эффекта следующий шаг возможен в
следующем цикле. Изменение состава/набора нулей требует разбора.

Доступен ручной тест одного цикла и расписание через целое число часов.
Оно работает только при действующем сеансе с ключом; см. hourly-schedule.md. Продление 30-дневного таймера ограничений также не реализовано.
Методы записи новой WB-ссылки/жалобы в публичной спецификации не найдены.
Собственные внешние ссылки требуют Premium Pro при использовании prices/details.

## Проверки

API-контракты сверялись с официальной спецификацией от 12 ноября 2026 года.
Автономные проверки включают создание после удаления, запись/восстановление ID,
общий коэффициент внутри кампании, изоляцию кампаний, ограничение шага, собственные
WB-ссылки, отсутствие индекса, неизвестный результат записи и отсутствие ключей
в сохранённых/возвращаемых данных.

В браузере на демонстрационном API выполнены создание кампании, добавление товара,
изменение её коэффициента, отказ от слишком большого шага, переключение, снятие
галочки, проверка несохранённого поля и мобильный вид. Реальные ключи не применялись.

## Коэффициент и подсветка в 0.2.3

Рабочая сетка 0,01 выбрана по наблюдению пользователя; Swagger не задаёт точность
хранения float. Значение 0,958 не округляется для записи. Только погрешность float32
до 0,000001 около сотой доли нормализуется при сравнении. Реальное значение вне
сетки остаётся видимым и блокирует автоматическую коррекцию.

`change_coefficient(..., manual=True)` разрешает явный ручной выбор любой ступени;
по умолчанию действует автоматический предел 0,01. Запись выполняется один раз,
подтверждение — до пяти чтений с паузами по секунде. `CoefficientReadbackError.change`
содержит previous/requested/actual/status; неизвестный результат не переотправляется.
Веб-адаптер сохраняет намерение, показывает фактический ответ и даёт обновить его
чтением. Явный выбор уже текущего значения не пишет в Ozon и снимает старое ожидание.

Индивидуальные индексы сравниваются без округления: [0,980; 1,010] зелёные,
остальные числа оранжевые, пропуски серые. Крайние значения включены.

## Дополнительные цены в 0.2.4

В таблице появились `wb_price` и `ozon_customer_price` с валютой и источником.
Это необязательное обогащение через `own_price_details(api, skus)` (Premium Pro),
отделённое от обычных цен, индекса и управления стратегией. Пропуск этих цен
не меняет расчёт среднего и не блокирует запись при подтверждённой ссылке стратегии.
Отказ запасного источника ссылки не удаляет существующих участников.
Подробнее: [источники и поведение без подписки](premium-data.md).

## Вход и жизненный цикл в 0.3.0

`GE_SERVER_MODE=1` включает обязательный вход по Argon2id-хешу из `GE_AUTH_FILE`.
Настройки `GE_PUBLIC_ORIGIN` и `GE_URL_PREFIX` задают точный HTTPS-origin и подпуть.
API требуют аутентифицированную сессию; POST также проверяют CSRF и Origin.
Ключ остаётся в памяти SellerAPI и не возвращается в JSON браузеру. Рекурсивное
редактирование ответов API убирает случайно отражённый ключ; ввод всегда маскируется.

`SellerAPI.close()` очищает ссылки на Client-Id/API-ключ, журнал и запрещает новые
запросы. Веб-адаптер вызывает его при выходе, истечении сеанса, отключении кабинета
и завершении приложения. TTL: 30 минут неактивности, абсолютный срок 8 часов.
Уже отправленный запрос может завершиться; автоматического повтора записи нет.
Периодическая очистка каждые 15 секунд действует и без новых запросов браузера.

## Интервальное расписание в 0.4.0

[API и правила запуска](hourly-schedule.md). Метаданные расписания и cycle_states
общие для всех действующих сеансов одного кабинета. Запуск отмечается на диске
до отправки в пул, а автоматическая операция использует отдельный guard для
отключения без закрытия ручного подключения. Ключи не записываются и срок входа
не продлевается планировщиком или опросом статуса.

Для автономного второго этапа: [подробный разбор хранения ключей](external-key-storage.md).
