# Средний индекс участников общей стратегии

Актуальные правила после уточнений пользователя 12–13 ноября 2026 года:

- Каждая кампания — отдельная стратегия WB со своим выбранным составом.
- Коэффициент общий внутри кампании; текущее значение читается из её стратегии.
- Рабочие границы коэффициента **0,94–1,00**, сетка и максимальный автоматический шаг **0,01**.
- Среднее индекса — **только по фактическим участникам стратегии**, без нулей.
- Целевой диапазон среднего **[0,98; 1,01] включительно**, внутренняя цель **0,995**.
- С версии 0.4.0 интервал для каждой кампании выбирается пользователем: 1–168 часов.
  На первом этапе запуски требуют действующего сеанса с ключом; [правила расписания](hourly-schedule.md).

Ранее рассматривался весь ассортимент и отдельные стратегии на SKU. Эта гипотеза
заменена правилами выше: теперь можно создавать и выбирать несколько кампаний. [Описание реализации и интерфейса](website-integration.md).

## Источник данных AJ

Колонка AJ: «Ценовой индекс товара на рынке на мои товары».
Соответствующее по смыслу поле Seller API:

```text
POST /v5/product/info/prices
items[].price_indexes.self_marketplaces_index_data.price_index_value
```

Перед автоматическим управлением требуется парная сверка нескольких товаров
со свежим шаблоном, полученным примерно одновременно с API. Схема API описывает
«Цену вашего товара на других площадках» и «Значение индекса цены», но не гарантирует
точность отображения AJ или диапазон 0,01–1,99 из шаблона. До сверки не нужно
самостоятельно обрезать значения API или заменять их другим индексом.

Не подходят вместо него: `external_index_data` (чужие товары), `ozon_index_data`
(сравнение на Ozon), `weight_index[].self_wb_index` (другой индекс WB).
В успешном ответе пользователя одновременно встречались собственный индекс
1,03 и `self_wb_index ≈ 0,956708`. Совпадение WB-ссылки не делает эти поля равными.
Веса `weight_percent` не используются: требуется обычное среднее.

## Знаменатель и полнота

```text
Участники = product_id из /v1/pricing-strategy/products/list
V = подтверждённые числовые индексы этих товаров, кроме ровно нуля
M = сумма(V) / количество(V)
Успех = 0.98 <= M <= 1.01
```

Предварительное округление среднего не используется. Не включённые в стратегию
товары не влияют на показатель. Снятая галочка до применения ещё не меняет
фактический состав. Несколько SKU одного product_id не размножают один товар.
Пропуски и неполные ответы не превращаются в нули: они блокируют регулирование.
Если все индексы нулевые, среднего нет и записи коэффициента нет.

В присланном фрагменте шаблона 29 строк: 28 ненулевых, один ноль, сумма 30,30,
среднее **1,082142857…**. Это только иллюстрация арифметики: фрагмент не определяет
текущий состав стратегии и не используется для назначения коэффициента.

## Сбор данных и управление

Товары стратегии возвращаются одним списком product_id. Цены и индексы читаются
по этим ID пакетами до 1000 через `/v5/product/info/prices`; соответствие SKU и
артикулов — через `/v3/product/info/list`. В массовом каталоге использовать
`total_items`: устаревший `total` по документации отключается 23 ноября 2026 года.
Скачивание XLSX для регулярного расчёта не требуется.

Коэффициент меняет `/v1/pricing-strategy/update`: передаются strategy_id, текущее
имя и полный список конкурентов. Основной модуль работает с одним выбранным WB,
сохраняет имя стратегии, проверяет состав перед изменением и перечитывает
коэффициент после записи. Диапазон **API** 0,5–1,2 шире рабочего диапазона
пользователя; выход за **0,94–1,00** в реализации запрещён.

Рабочая сетка: 0,94; 0,95; …; 1,00. За автоматический цикл:

```text
если 0.98 <= M <= 1.01: оставить k
если M > 1.01: k_new = max(0.94, k_current - 0.01)
если M < 0.98: k_new = min(1.00, k_current + 0.01)
```

Вручную пользователь может выбрать любую ступень внутри границ. Сетка выбрана
по наблюдению округления в кабинете; Swagger точность хранения не гарантирует.
0,958 не округляется для отправки. Погрешность float32 около сотой доли учитывается
при сравнении; реальное значение вне сетки видно и блокирует автоматическую запись.

Это приближение, а не гарантированная формула Ozon. Покупательская цена зависит
также от скидок, округления и нижних ограничений. Реакцию на малое изменение
нужно измерить в кабинете. После изменения сохраняется ожидание результата;
повторная коррекция по тем же данным не выполняется. При новых ценах/индексах
сначала фиксируется наблюдение, следующий шаг возможен в следующем цикле.
Изменение набора ненулевых участников требует разбора, а не слепого продолжения.

Если достигнута граница коэффициента, а среднее вне вилки, результат —
«предел регулирования», не успех. Нижние цены не уменьшаются ради среднего.
Индивидуальные индексы могут быть вне вилки: правило относится к среднему.
Две проверки в день не обеспечивают непрерывное удержание показателя между ними.

## Проверка соответствия WB

После включения сопоставление читается из `pricing-strategy/product/info`,
при пустой ссылке — из собственных полей Premium Pro `/v1/product/prices/details`.
Сравнение по артикулу WB. При неверной или не подтверждённой за время ожидания
ссылке исключается конкретный товар, остальные участники продолжают работать.
До подтверждения состава, ссылок и ограничений коррекция коэффициента заблокирована.
