# Great Equalizer: проверка покупательской цены WB

Тестовый код получает цены напрямую с витрины Wildberries:

```text
https://www.wildberries.ru/__internal/card/cards/v4/detail
```

Используется готовое `products[].sizes[].price.product / 100` — наблюдаемая цена после СПП. Отдельно знать процент СПП не требуется. Код рассчитывает оценку цены с WB Кошельком: ещё −3%, с округлением до рубля. Это расчёт по согласованному условию, а не значение поля `wallet` в ответе WB.

## Установка

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## Jupyter

Откройте [notebooks/wb_prices.ipynb](notebooks/wb_prices.ipynb) в своём Jupyter и выберите окружение с установленным `requests`. При необходимости установите зависимости в выбранное ядро через `%pip install -r ../requirements.txt`, если текущая папка ядра — `notebooks`.

В ноутбуке `x_wbaas_token` и `deviceid` вводятся через скрытый ввод. User-Agent берётся из той же браузерной сессии. Регион `dest` задаётся явно: для сравнения цен он должен оставаться одинаковым.

## Командная строка

Сохраните свой рабочий Python-запрос из DevTools в `.local/browser_request.py`. Эта папка игнорируется Git. Убедитесь, что экспорт содержит буквальные словари `cookies` и `headers`.

```bash
python wb_prices.py --context-file .local/browser_request.py --dest=-1257786 732445767 732449137 386287758
```

Исходный файл разбирается как текст и **не выполняется**. Из cookies отправляется только `x_wbaas_token`; сохраняются заголовки исходного примера, кроме `Authorization` и `Cookie`. Токены и заголовки не выводятся. Вместо файла можно задать локальные переменные `WB_WBAAS_TOKEN`, `WB_DEVICE_ID`, `WB_USER_AGENT`.

Ответ содержит цены по артикулу и ID размера, регион, время получения и список отсутствующих артикулов. Отсутствующая цена остаётся `null`. Код завершения: `0` — все цены получены, `1` — ошибка запроса/конфигурации, `2` — неполные данные.

## Что уже установлено

В локальных проверках пользователя запрос цен работал без `Authorization` с одной cookie `x_wbaas_token`. Сочетание рабочего токена из запроса цен и гостевого `deviceid` также работало. Подстановка другой гостевой пары давала HTTP 498. Автоматическое получение подходящего токена без входа пока не подтверждено.

10 ноября 2026 года выполнены два реальных запроса из облачной среды с предоставленными данными сессии: вариант с заголовками исходного примера получил HTTP 200 и цены всех шести тестовых артикулов; вариант `BrowserContext.create`, используемый в ноутбуке, также получил HTTP 200 и цены трёх запрошенных артикулов. Регион в обеих проверках — `dest=-1257786`. `Authorization` не отправлялся. Это подтверждает запросы с существующим токеном, но не автоматическое получение нового токена и не бессрочную работу сессии.

Это внутренний маршрут сайта, а не документированный Seller API. Код не обновляет токен, не входит в аккаунт, не меняет цены на WB или Ozon и не повторяет запросы автоматически при 403/498. TLS-проверка и настройки сетевого прокси сохраняются.

Не добавляйте в Git реальные cookies, токены, экспортированные запросы или вывод ноутбука с данными сессии. Перед сохранением ноутбука очищайте вывод ячеек с вводом.
