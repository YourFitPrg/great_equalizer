# Great Equalizer: цены WB и подготовка обновления цен Ozon

## Локальный сайт Ozon / WB

[Скачать версию 0.2.1 для Windows](exports/ozon-local-web-0.2.1.zip) · [Инструкция](README_LOCAL.md)

Нужен Python 3.10+. Распакуйте архив и запустите `run_local.bat`.
Сайт откроется на `http://127.0.0.1:8765`: сначала деморежим, затем можно подключить свой Ozon.
Создание и выбор кампаний, товары, ограничения и коэффициенты доступны в браузере.
В версии 0.2.1 исправлена ошибочная блокировка добавления товара в стратегию.

Тестовый код получает цены напрямую с витрины Wildberries:

```text
https://www.wildberries.ru/__internal/card/cards/v4/detail
```

Используется готовое `products[].sizes[].price.product / 100` — наблюдаемая цена после СПП. Отдельно знать процент СПП не требуется. Код рассчитывает оценку цены с WB Кошельком: ещё −3%, с округлением до рубля. Это расчёт по согласованному условию, а не значение поля `wallet` в ответе WB.

## Jupyter

Откройте [notebooks/wb_prices.ipynb](notebooks/wb_prices.ipynb) в своём Jupyter и выберите окружение с установленным `requests`. При необходимости установите зависимости в выбранное ядро через `%pip install -r ../requirements.txt`, если текущая папка ядра — `notebooks`.

В ноутбуке `x_wbaas_token` и `deviceid` вводятся через скрытый ввод. User-Agent берётся из той же браузерной сессии. Регион `dest` задаётся явно: для сравнения цен он должен оставаться одинаковым.

## Командная строка

Сохраните свой рабочий Python-запрос из DevTools в `.local/browser_request.py`. Эта папка игнорируется Git. Убедитесь, что экспорт содержит буквальные словари `cookies` и `headers`.

```bash
python wb_prices.py --context-file .local/browser_request.py --dest=-1257786 732445767 732449137 386287758
```

Исходный файл разбирается как текст и **не выполняется**. Из cookies отправляется только `x_wbaas_token`; сохраняются заголовки исходного примера, кроме `Authorization` и `Cookie`. Токены и заголовки не выводятся. Вместо файла можно задать локальные переменные `WB_WBAAS_TOKEN`, `WB_DEVICE_ID`, `WB_USER_AGENT`.

Ответ содержит цены по артикулу и ID размера, регион, время получения и список отсутствующих артикулов. Отсутствующая цена остаётся `null`. Код завершения: `0` — все цены получены, `1` — ошибка запроса/конфигурации, `2` — неполные данные.

## Что уже установлено

В локальных проверках пользователя запрос цен работал без `Authorization` с одной cookie `x_wbaas_token`. Сочетание рабочего токена из запроса цен и гостевого `deviceid` также работало. Подстановка другой гостевой пары давала HTTP 498. Автоматическое получение подходящего токена без входа пока не подтверждено.

10 ноября 2026 года выполнены два реальных запроса из облачной среды с предоставленными данными сессии: вариант с заголовками исходного примера получил HTTP 200 и цены всех шести тестовых артикулов; вариант `BrowserContext.create`, используемый в ноутбуке, также получил HTTP 200 и цены трёх запрошенных артикулов. Регион в обеих проверках — `dest=-1257786`. `Authorization` не отправлялся. Это подтверждает запросы с существующим токеном, но не автоматическое получение нового токена и не бессрочную работу сессии.

Это внутренний маршрут сайта, а не документированный Seller API. Код не обновляет токен, не входит в аккаунт, не меняет цены на WB или Ozon и не повторяет запросы автоматически при 403/498. TLS-проверка и настройки сетевого прокси сохраняются.

Не добавляйте в Git реальные cookies, токены, экспортированные запросы или вывод ноутбука с данными сессии. Перед сохранением ноутбука очищайте вывод ячеек с вводом.

## WB → сцепка → шаблон Ozon

Этот этап использует уже скачанный шаблон Ozon. Код входа в ЛК и скачивания шаблона можно подключить перед расчётом; здесь вход и загрузка обновлённых цен в Ozon не выполняются. Данные сессии WB пока вводятся вручную.

1. В `inputs/mapping.xlsx` поместите таблицу соответствий. На листе `Лист1` ожидаются A — артикул продавца Ozon, B — SKU Ozon, C — артикул WB. Читаются готовые значения формул; для отсутствующего результата VLOOKUP можно восстановить единственную точную связь из листа `Лист2`.
2. В `inputs/ozon_template.xlsx` поместите свежий шаблон Ozon. На листе `Товары и цены` используются B — SKU, P — текущая предельная цена, R — текущая цена реализации, AY — новая предельная цена.
3. Запустите [ноутбук полного расчёта](notebooks/equalize_ozon.ipynb) или команду ниже.

```bash
python price_equalizer.py \
  --mapping inputs/mapping.xlsx \
  --template inputs/ozon_template.xlsx \
  --context-file .local/browser_request.py \
  --dest=-1257786 \
  --output outputs/ozon_updated.xlsx \
  --audit outputs/calculation.csv \
  --save-snapshot outputs/wb_snapshot.json
```

Команда приведена для shell Linux/macOS. В Jupyter используйте ноутбук, в PowerShell запишите команду в одну строку. Папки `inputs`, `outputs`, XLSX и CSV исключены из Git.

По согласованному правилу **цель — покупательская цена WB с расчётной скидкой Кошелька 3%; цены меняются в обе стороны**. Формула для каждой строки:

```text
Коэффициент Ozon = R / P
Эффективная скидка Ozon, % = (1 − R / P) × 100
Цель WB = округлить(price.product / 100 × 0,97) до рубля
AY = округлить(Цель WB × P / R) до копейки
```

`R / P × 100` — процент оставшейся цены, а не процент скидки. Расчёт предполагает сохранение текущего коэффициента Ozon после изменения предельной цены. Фактическое поведение площадки проверяется повторной выгрузкой после применения: акции или скидки могут изменить коэффициент.

В файл для загрузки записываются только рассчитанные AY. Структура шаблона, стили, инструкции и остальные ячейки сохраняются. Исходные файлы и существующие AY не перезаписываются. Технически меняются только соответствующие ячейки в XML внутри XLSX: это также сохраняет особенности стилей оригинального шаблона, которые могут не поддерживаться обычными Excel-библиотеками.

Отдельный CSV содержит исходные значения, связку SKU → WB, коэффициент, целевую цену, расчётную цену реализации и причину пропуска. При неоднозначных ценах размеров WB минимальная цена или средняя не подставляются: нужна дополнительная сцепка с ID размера. Отсутствующие цены и отсутствующие связи не превращаются в нули.

Если новая AY ниже действующего ограничения акций S при U=`ДА`, это отмечается в `note` как `new_limit_below_current_promotion_floor`. Ограничение акций и его настройки не меняются автоматически. Его влияние на ручное обновление и последующие акции нужно проверить в Ozon; это отдельный параметр, не часть формулы выравнивания.

Для повторного расчёта по уже сохранённым ценам замените `--context-file` на `--snapshot outputs/wb_snapshot.json` и задайте новые пути выходных файлов. Этот режим использует снимок, а не запрашивает актуальные цены. `--target without-wallet` и `--direction raise-only` — дополнительные явные режимы; по умолчанию применяются согласованные `wallet` и `both`.
